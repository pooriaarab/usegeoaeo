# geoaeo v0.2 — "proper thing" feature build

Goal: move geoaeo from a solid v0.1 to a tool an indie hacker OR an enterprise installs
(`npm i geoaeo`) and trusts to make an app genuinely SEO + GEO + AEO optimized.

Workers: build ONLY your unit, ONLY under its paths, **write files only — no git, no npm,
no build.** Match the existing code style. Every new capability needs a vitest test in
`tests/`. The advisor (Opus) owns the audit-scoring brain, reviews every diff, and integrates.

## Match the existing patterns (read these first)

- Generators: `src/generators/{llms,robots,sitemap,jsonld,webmcp}.ts` + `index.ts` barrel.
  Each exports a pure `generateX(config)` returning a string. Config type in `src/config.ts`.
- CLI wiring: `src/cli.ts` (commander). Gen dispatch: `src/commands/gen.ts`.
- MCP tools: `src/mcp.ts`. Tests: `tests/generators.test.ts` (copy its shape).
- Never invent config fields that `src/config.ts` `SiteConfig` does not define; if a new
  field is needed, add it there with a sensible default and document it.

## Units

### F2 — more JSON-LD kinds  (owner: kimi)
Path: `src/generators/jsonld.ts` (+ `tests/generators.test.ts` additions).
Extend the JSON-LD generator with these schema.org kinds (it has software/product/faq/
breadcrumb): **Organization, WebSite (with `potentialAction` SearchAction sitelinks box),
Article, HowTo, Person, Review**. Keep the existing `--type` switch working; add the new
kinds to it. Each kind = valid schema.org JSON. Add one test per new kind asserting the
`@type` and required fields. Pure functions only. Do NOT touch audit.ts.

### F3 — more generators  (owner: pi / grok-4.6)
Paths: `src/generators/{ogimage,rss,hreflang,mdmirror}.ts`, export them from
`src/generators/index.ts`, wire into `src/commands/gen.ts` + `src/cli.ts` `--type`/artifact
list, add tests.
- `ogimage` — return an SVG string for an Open Graph card (title + site name from config).
  SVG only (no binary/PNG deps).
- `rss` — an RSS 2.0 / Atom feed string from config (site + a pages/items list).
- `hreflang` — given config locales, return the `<link rel="alternate" hreflang=...>` block.
- `mdmirror` — given a page's title + body, return a clean Markdown mirror string.
Each pure, each with a test. Do NOT touch audit.ts or jsonld.ts.

### F4 — more init frameworks  (owner: muse)
Path: `src/commands/init.ts` (+ a test if practical).
`init` currently scaffolds Next.js App Router and static sites. Add detection + scaffolds
for **Astro, SvelteKit, Nuxt, Remix** (detect by their config file / dir markers, mirror the
existing Next branch: write the framework-idiomatic route/endpoint files that emit
llms.txt, sitemap, robots, JSON-LD, and .md mirrors). Keep existing behavior unchanged;
existing files stay unless `--force`. Do NOT touch generators or audit.

## Advisor-owned (NOT delegated)

- F1 — answerability / GEO scoring in `src/audit.ts`: direct-answer detection, Q&A framing,
  content chunkability, freshness/dated-content signal, author/E-E-A-T presence. Replaces the
  crude "h1 + earlyFaq" single check with a real answerability sub-score.
- F5 — deeper audit detectors + weights: hreflang, heading hierarchy, image alt, meta-robots/
  noindex, canonical validity, security.txt/humans.txt, RSS. Advisor owns all weight changes
  (weights must keep summing to 100).
- F6 — `audit --ci --min-score N` (exit non-zero below threshold), `LICENSE` (MIT), README
  rewrite (unscoped `npm i geoaeo`, full feature list, badges).
- E2E test — spawn the built CLI against a fixture site; assert audit/gen/init behavior.
